# enterprise-agent 智能体架构规划

> 目标：不只是一套 RAG 问答，而是一个**回答准确、执行准确、能自我优化**的企业智能体平台。
> 本文档是长期蓝图，实施按阶段推进，每阶段结束跑全量回归。

---

## 一、设计原则（一晚上攒下的教训提炼）

1. **模型只做生成，决策与校验交给代码**——模型决策不可靠已被反复验证（工具调用、格式、编造）
2. **每条链路闭环**：意图 → 计划 → 执行 → 校验 → 学习，每步可观测、可回退
3. **评测驱动**：没有评测用例的改动不进主干；回归集只增不减（棘轮效应）
4. **失败可见**：一切行为落审计，一切异常有告警，一切降级有日志

## 二、三大能力的具体设计

### 1. 回答准确（Grounding）

| 环节 | 设计 | 状态 |
|---|---|---|
| 检索 | 稠密(BGE-M3) + BM25 混合召回 + bge-reranker 精排 | 阶段1稠密已通，BM25 待补 |
| 检索参数自适应 | top_k / 阈值不写死：用检索评测集自动搜索最优组合，只接受不劣化变更 | P2 |
| 防编造 | 缺失术语锚定校验 + 鉴伪断言删除 + 图谱回声剥除 + 过度删除回退 | ✅ 已移植 |
| 引用溯源 | 答案中每个事实句绑定来源 chunk；前端可点击溯源 | P3 |
| 评测回归 | 问答评测集（断言式：不含XX/必须命中XX/路由=XX）+ 检索评测集，一键跑分 | P2（地基，最先做） |

### 2. 执行准确（Agentic Execution）

| 环节 | 设计 | 状态 |
|---|---|---|
| 意图路由规则表 | `模式正则 → 处理器` 配置化：新增一类问题=加一行配置，不写代码 | P2 |
| SOP 状态机 | 请假四步（查员工→校验规则→提交→回执核对），每步确定性校验 | P4 |
| 工具策略 | 白名单 + 参数校验 + 超时重试 + 提交类幂等（防重复提交）+ 流程词禁调数据工具 | P4 |
| 执行审计 | 每次工具调用记录入参/出参/耗时，执行结果可回放 | P4 |
| 防"编造成功" | 校验失败时确定性输出失败原因，**禁止**模型把失败改写成"已提交" | P4 |

### 3. 自我优化（Learning Loop）——本次规划的核心增量

三个自动化闭环：

**闭环 A：反馈回流（人工 → 知识）**
```
用户 👍/👎/纠正 → 审核 → 知识库回流 / 守卫规则沉淀 / 评测用例新增
```
- 👍 采纳问答 → 自动入库
- 👎 或用户纠正 → 自动生成回归用例（问句 + 期望断言），下次必测

**闭环 B：评测驱动（数据 → 参数）**
```
回归跑分 → 参数搜索（top_k/阈值/提示词版本）→ 只接受不劣化变更 → 记录版本基线
```
- 每次模型/提示词/参数变更自动跑全量回归，输出 diff 报告
- 长期沉淀"哪些参数组合在什么数据上最优"

**闭环 C：缺口发现（问答 → 知识）**
```
答不上问题聚类 → 知识库健康度报告 → 自动生成补库建议（要补什么文档）
```
- 阈值兜底（"暂无法回答"）发生即记录，每周聚类出 top 缺口

**配套：成本/延迟自治**
- 每次 LLM 调用记录模型/字符量/耗时 → 看板
- 成本或延迟超阈值自动降级（大模型 → 小模型；校验层可关闭）

## 三、Python 工程分层（目标结构）

```
app/
├── intent/          # 意图路由规则表（配置化）
├── retrieve/        # 混合检索 + 重排 + 参数自适应
├── plan/            # SOP 状态机引擎
├── execute/         # 工具执行器 + 策略（重试/幂等/白名单）+ 执行审计
├── verify/          # 答案校验 + 执行校验（确定性守卫在此）
├── learn/           # 评测引擎 + 反馈处理 + 缺口分析 + 参数调优
├── channels/        # 渠道适配：web(SSE) / feishu(WS+卡片)
├── data/            # 存储访问：milvus / mysql / redis / neo4j / oa
└── core/            # llm / config / guards / audit
```

分层原则：**每一层可独立测试**。intent 的规则表是纯数据，verify 的守卫是纯函数——评测引擎可以对它们单独跑用例。

## 四、实施阶段（每阶段一个可运行交付，结束跑全量回归）

| 阶段 | 内容 | 交付物 |
|---|---|---|
| **P1 ✅** | 骨架 + 核心 QA（检索→生成→校验→守卫→SSE） | 已完成 |
| **P2 评测基座**（下一步） | ① 问答回归集 + 断言跑分器 ② 意图路由规则表化 ③ 检索参数自适应 | `learn/` 雏形 + 一键评测命令 |
| **P3 反馈环** | 👍👎/纠正采集 → 用例沉淀/知识回流 + 引用溯源 | 反馈闭环可用 |
| **P4 执行层** | SOP 引擎 + 工具策略 + 执行审计 + 防编造成功 | 请假全流程可用 |
| **P5 飞书渠道** | WS 长连接 + 卡片回复 + 图片 OCR + 文档生成 | 飞书闭环可用 |
| **P6 学习环收口** | 缺口发现 + 成本/延迟看板 + 模型路由降级 | 三闭环全部运转 |

**为什么 P2 最先做**：自我优化的前提是"可测量"。没有评测基线，一切"优化"都是玄学。回归集就是这套系统的免疫系统——每修一个坑锁一条用例，之后每次改动自动验证不复发。

## 五、评测用例形态（示例）

```json
{
  "id": "guard-003",
  "query": "高血压应该注意什么",
  "expect": {
    "route": "KNOWLEDGE_QA",
    "sources_include": ["内科学.pdf"],
    "answer_not_contain": ["（属于）：", "伪名言", "暂无法回答"],
    "answer_contain": ["血压"],
    "max_seconds": 30
  }
}
```

断言式用例覆盖：路由正确性、来源命中、防编造、响应时限。跑分器输出通过率 + 失败明细，失败用例即待修清单。
