# 事故复盘（postmortem）0001：路由预判正则三轮补丁全废

状态：已解决

## 摘要

NL2SQL 数据面为省一次模型调用加了预判正则预闸，先后三轮形态（白名单词表→黑名单反转→负向 lookahead）全部失败：口语碎片漏预闸导致标准问法兜底、黑名单误伤标准问法、用户连续飞书实况暴怒。最终删除全部预判，改为无预闸架构（每层按自身定义自判）。防回归产物：变体矩阵 test_matrix_human.py（290 用例）+ 回归 guard 断言翻新。

## 影响

用户飞书连续测出「王强是干什么的」「赵敏的联系方式」「公司有几位员工」全部「暂无法回答」——标准员工查询大面积失灵。用户三次暴怒，最后定性：「为什么要写死一些去判断？为什么不从知识库里去定义你回答什么，从 skills 中去看你能干什么？越改越像人工智障」。

## 时间线

- 2026-08-19 凌晨：能力总线退役，员工/报销/经营问答并入 NL2SQL。为省调用加 _FACT_QUERY 白名单预闸（产品/价格/多少/电话…）。
- 同日：真机实测「王强什么时候入职的」答兜底——预闸缺「什么时候」。补词。
- 同日：用户贴「李娜部门的报销」答兜底——跨表问法+数据错位+预闸缺词三层叠加。
- 变体矩阵第一轮（198/260）：口语碎片「几位/哪年/干什么/联系方式」全漏预闸——白名单路线被判死，反转成黑名单。
- 变体矩阵第二轮：黑名单「是什么」误伤「王强是什么时候入职的」（标准问法快速失败）。
- 第三轮加负向 lookahead 补丁时，用户打断并暴怒定调。删除全部预判正则，无预闸架构落地，变体矩阵 290/290。

## 根因

1. **预判与执行分离的反模式**：路由层用正则预测「模型能否生成 SQL」，而模型能力（能否答这个问法）只有模型自己知道。预判词表永远落后于真实问法——这是结构性错误，不是词表不够全。
2. **我重复打补丁而不是质疑机制**：白名单失败后没有停下来问「预判本身对不对」，而是反转成黑名单、再打 lookahead 补丁。用户第三轮才叫停——「改的是类不是实例」的定调（2026-08-18）没有贯彻到机制层面。
3. **缺少模拟真人的变体测试**：同一问法跑 10 遍只测采样稳定性，测不出问法形态缺口——口语碎片漏预闸全部逃过原有测试。

## 已添加的防护措施

1. **无预闸架构**（结构性修复）：NL2SQL 无条件尝试，模型自判（空模板=漏回）；知识问答兜底；SOP 关键词注册（详见 docs/decisions/implemented/2026-08-19-no-pregating-routing.md）。
2. **变体矩阵** `scripts/test_matrix_human.py`：29 项功能 × 3-6 种口语变体轮换 × 10 次——模拟真人问法，同一字符串重复跑不再算数。
3. **回归用例翻新**：guard-001/002/003/004 断言锁新口径（数据面答案形态）。
4. **CLAUDE.md 第 0 条**：「要智能」定调 + 交付前穷举自测铁律。

## 教训

1. 预判正则永远不完整——任何「预测模型能力」的词表机制都是打地鼠，能力判定权必须归能力本身（模型自判/技能注册/检索兜底）。
2. 补丁打第二遍就要停下来质疑机制——补丁数量是机制错误的第一信号。
3. 测试必须模拟真人（变体问法），同一字符串重复跑是自欺。
4. 用户实况是最高优先级信号：三次暴怒的每一轮都对应一类机制缺陷，修实况前先想「这是什么类问题」。
