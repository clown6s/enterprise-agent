# 事故复盘（postmortem）

借鉴 deepseek-harness `docs/postmortem/`（2026-08-19 落地，见 docs/dsh-highlights.md 二-4）。

## 入选标准（防止流水账）

只有同时满足以下条件的 bug 才写复盘：

1. **隐蔽**——正常测试/审查没拦住，逃到生产/真机
2. **系统性**——是一类问题的表现，不是一次性笔误
3. **重新发现代价高**——不记下来，后人会再花一遍排查时间

## 骨架

每篇按固定结构（30 秒能读完摘要）：

```
# 事故复盘（postmortem）NNNN：<一句话标题>
状态：已解决

## 摘要（30 秒执行摘要：发生了什么、根因、修复）

## 影响（用户实际感受到的后果）

## 时间线（以持久化日志/事件序列为依据，不反推意图）

## 根因（为什么测试没拦住、为什么逃到生产）

## 已添加的防护措施（具体到修复/测试/规则，不写「加强意识」类空话）

## 教训
```

## 硬性要求

**每篇复盘必须产生至少一条防回归的测试或规则**——可以是新回归用例、不变量检查、
守卫规则或文档规范。复盘文档本身不算防护。这条纪律防止复盘沦为叙述文。
