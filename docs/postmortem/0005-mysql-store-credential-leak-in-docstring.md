# 事故复盘（postmortem）0005：mysql_store.py docstring 泄露凭据

状态：已解决

## 摘要

`app/mysql_store.py` 模块 docstring 中写入了真实管理员凭据（用户名/密码）：
`现有 admin 账号（admin / Admin@2026）直接可用`。CLAUDE.md 明确要求
"凭据走文件传递，绝不内联到 shell 命令"，但 docstring 里的凭据违反了这条铁律。
扫描清理时发现。

## 影响

凭据进入 git 历史——任何有仓库读权限的人（包括未来的 AI 协作者）都能看到
管理员用户名和密码。密码虽然已可从 .env 读取（不是唯一泄露路径），但 docstring
泄露是"代码即文档"的反面——代码里的凭据比 .env 更容易被复制/粘贴/分享。

## 时间线

- 2026-08-18（推测）：mysql_store.py 创建时，docstring 解释密码算法和现有账号，
  为方便开发者快速上手，直接写了 admin/密码。
- 2026-08-20：扫描清理时发现，删除凭据，改为"凭据从 .env 读取，不内联到代码"。

## 根因

1. **便利性驱动写凭据**：开发者写 docstring 时为了"一眼看懂怎么用"直接写了
   用户名/密码——便利性优先于安全，是凭据泄露的最常见根因。
2. **CLAUDE.md 铁律未覆盖 docstring**：铁律说"绝不内联到 shell 命令"，
   但没有明确说"也不写在 docstring/注释/变量名里"——铁律的覆盖面不够。
3. **无凭据扫描**：项目没有 secret scanner（如 git-secrets / truffleHog），
   凭据进了 git 历史无人发现。

## 已添加的防护措施

1. **docstring 清理**（`app/mysql_store.py`）：删除凭据，改为"凭据从 .env 读取"。
2. **CLAUDE.md 铁律扩展**（关键坑段）：明确"凭据不内联到 shell 命令 / docstring /
   注释 / 变量名"——覆盖面从"shell 命令"扩展到"任何代码可见位置"。
3. **config.py OA_* 默认值清理**：`OA_PASSWORD` 默认值从 `"123456"` 改为空串
   （退役 + 去弱默认密码）。

## 教训

1. **凭据只该出现在 .env 和运行时环境变量里**——docstring/注释/变量名都不是
   凭据的合法位置。写代码时"为方便"直接写凭据是安全事件的第一根因。
2. **安全铁律的覆盖面要够宽**——"不内联到 shell 命令"不够，要"不写在任何
   代码可见位置"。每发现一个新泄露位置就扩展铁律覆盖面。
3. **git 历史是永久泄露**——即使删除文件内容，git log 仍可追溯。密码应轮换，
   不能只删不换。
