# Problem

管理员删除知识库文档时，原接口只删除 Milvus chunks，Neo4j 中由该文档生成的关系继续参与 Graph RAG，造成已删除内容残留。

# Decision

图谱关系写入 `doc_id` 属性，并按实体、关系类型和文档 ID 隔离 MERGE。管理员删除文档时，在删除 Milvus chunks 后调用图谱删除：只删除该文档的 `RELATES` 关系，再清理没有任何关系的共享实体。实体节点仍按名称共享，因此仍被其他文档关系引用的实体不会被删除。非法文档 ID 和 Neo4j 异常按软失败处理并返回状态，不回滚已完成的 Milvus 删除。

测试阶段不存在需要迁移的旧图谱数据，本次不增加迁移逻辑。

# Alternatives

- 仅删除 Milvus：实现最少，但图谱会返回已删除文档事实。
- 每次删除后清空并重建整个图谱：隔离简单，但代价高且会影响其他文档。
- 将实体节点也按文档复制：避免共享清理判断，但会造成实体重复、降低 Graph RAG 关联能力。

# Consequences

删除接口现在能同步清理文档归属关系，并报告图谱删除状态；共享实体在仍有其他关系时保留。Milvus 删除和 Neo4j 删除是独立软依赖，Neo4j 暂时不可用时不会撤销向量删除，但管理响应会暴露失败状态。
