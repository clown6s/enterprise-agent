# 决策：多行数据结果正文保留摘要，明细统一承载于表格

状态：implemented

## Problem

NL2SQL 多行结果同时以完整文本列表和结构化表格返回时，飞书/Web 会把同一批明细展示两遍。反过来，如果正文只写“共 N 条”，经营数据等结果又缺少回答对象，用户无法从正文知道这些行代表日期、营收还是其他字段。

## Decision

在 `app/service/nlsql.py` 中把多行结果统一拆成“摘要 + 表格”两层：

1. `try_answer_result()` 对多行结果只返回确定性摘要，不再在正文展开明细；完整行数据继续放入 `query_table` 结构化 payload，由渠道表格承载。
2. 摘要使用真实查询结果的中文列名，格式为“查询结果（N 条），包含列名，详情见下方表格”。列名来自注册表/结果列标签，不由模型生成。
3. 将摘要格式抽为 `_table_summary()`，供数据面和离线契约测试共同复用；列名为空时使用“数据”作为稳定兜底，避免生成空摘要。
4. 单行和空结果仍保持原有轻量文本口径；多行明细不再额外调用答案包装模型。

## Alternatives considered

1. 保留完整文本并隐藏表格：不同渠道的渲染能力不一致，仍可能重复或丢失结构化能力。
2. 只保留“共 N 条”：正文信息不足，经营数据类回归会退化为无法判断回答对象的泛化摘要。
3. 让模型生成多行摘要：列名和数量是确定性数据，交给模型会增加改写或编造风险；因此由代码直接生成。

## Consequences

+ 多行明细在渠道中只展示一次，表格仍保留表头、类型和全部行。
+ 摘要保留真实中文列名，经营数据等结果在正文中仍有可识别语义。
+ 不增加多行结果的 LLM 包装调用，延迟和数字改写风险保持不变。
− 正文不再直接列出多行明细，纯文本客户端若不渲染 `query_table` 需要显式支持表格 payload。
− 表格卡片 schema 和渠道渲染仍需通过 `scripts/test_data_table.py` 及真实飞书验证持续检查。
