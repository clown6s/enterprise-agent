# Problem

检索允许跨文档召回，但全局 rerank top-N 可能被单个长文档占满，其他相关文档无法进入上下文。直接降低分数阈值会引入噪音，按来源名称分组还会错误合并同名文档。

# Decision

保留现有召回、rerank 和 `RERANK_MIN_SCORE` 过滤语义。相关证据通过分数过滤后，再按 `document_id`（缺失时 source/title）做预算：优先保留各个尚未覆盖文档的最高分证据，单文档默认最多 2 条，再按分数补齐最终 4 条。rerank 候选窗口与最终输出数量分离，候选窗口默认 12；名词豁免和无 rerank 分支同样执行预算。实体/来源字段和前端协议不变。

# Alternatives

- 降低全局 rerank 阈值：会把噪音带入上下文。
- 固定返回多个来源：可能强行保留无关文档。
- 只按 source 分组：同名不同文档会被错误合并。

# Consequences

相关文档更有机会共同进入上下文，明确维度的覆盖闸门仍可安全拒答缺失证据。候选 rerank 数增加可能增加延迟，但有固定窗口和最终证据上限，不会无界增长。当前来源字段仍为兼容的文件名列表，内部命中保留 document_id/page/score。
