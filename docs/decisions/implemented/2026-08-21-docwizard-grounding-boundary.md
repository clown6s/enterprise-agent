# 决策：文档生成采用资料边界与统一事实校验链

状态：implemented

## Problem

文档生成链路直接把模型正文发布到云文档。即使提示词要求基于知识库，模型仍可能把建议写成资料要求，或输出系统无法证明的绝对来源声明（例如“完全依据资料”“未引入外部知识”）。文档生成若绕过问答校验和格式守卫，还会形成一条独立的防编造与格式漂移路径。

## Decision

在 `app/service/docwizard.py` 中采用“边界前置、统一收口”的生成机制：

1. 生成提示词把内容分为资料事实、资料整理和建议实践。资料事实必须能由资料定位；资料整理只允许重排或归纳；建议实践必须显式标注“建议”，不能冒充资料要求。
2. 生成后的证据集合统一使用知识库资料和用户要点。正文先复用 `app/service/verify.py` 的事实校验，再复用 `app/guards.py` 的确定性格式重建。
3. 增加确定性 `_clean_source_claims`，删除模型无法自行证明的绝对来源声明；正文不自行声明来源。当前文档生成结果的来源展示仍是后续跟进项，不把未实现的卡片/元数据投影当成本次交付事实。
4. 保留已有缺失术语/数字接地复核；校验结果为空或为兜底答案时不覆盖可交付正文，最终仍以确定性守卫收口。
5. 文档正文统一使用无序列表，与问答输出的 `guards.fix_output` 口径一致。
6. 初始生成 `_generate()` 接入上述收口；多轮 `revise()` 仍是独立回写路径，当前决策不宣称它已自动复用同一校验链，后续需单独补齐。

## Alternatives considered

1. 只加强生成提示词：不能保证模型遵守边界，也不能阻止绝对来源声明漏出。
2. 文档链路继续维护一套独立校验和格式规则：会与问答链分叉，后续修复容易漏接，违反流式/非流式和多入口同步原则。
3. 由模型自行声明资料来源：系统无法证明模型的绝对断言，属于把证据责任交给生成模型，因此不采用。

## Consequences

+ 资料事实、整理和建议的语义边界在生成阶段明确，建议不再伪装成制度要求。
+ 文档生成复用统一事实校验和确定性格式守卫，降低编造、残句和格式漂移风险。
+ 绝对来源声明由代码确定性清理，正文不再冒充系统证据。
+ 初始生成路径复用问答事实校验和格式守卫，降低编造、残句和格式漂移风险。
− 文档生成增加一次校验链调用，生成延迟和模型成本上升。
− 当前文档来源卡片/元数据投影与 `revise()` 回写校验仍是跟进债务；本决策不把它们误报为已交付能力。
− 校验仍依赖资料与用户要点的证据范围；跨文档拼接和资料本身错误不由本决策解决。
− 需要通过 `scripts/test_docwizard.py`、全量回归和真实链路持续验证，避免新入口绕过统一收口。
