# 结构化文档切分修复决策记录

## Problem

部分文档解析器会把同一物理行中的多个法律条文连接在一起。工作区改动虽增加了行内条文识别和续块元数据，但与历史实现叠加后留下重复、不可达函数体，降低可维护性并掩盖 QA 切分中的未初始化变量问题。

## Decision

保留现有 profile 注册表和公开函数签名，统一每个 profile 为一个实现；法律切分按可信条文起点拆分并保留条号、层级、页码及续块元数据；所有 profile 共享长度限制切分逻辑。

## Alternatives

- 继续在重复实现上追加局部补丁：改动小，但会继续保留不可达代码和行为漂移风险。
- 将所有文档退回通用段落切分：实现简单，但会丢失法律条号、层级、问答和术语元数据。

## Consequences

结构化预览和上传阶段获得稳定、可追踪的条文块；续块不再依赖人为添加的标题文本，而通过明确元数据关联。模块代码体量减少，后续 profile 修改只需维护单一实现；行为变化需通过结构化切分回归测试和通用管线测试共同验证。

本次后续修复还使 DOCX 中的显式分页符转换为 `[[page:N]]`，但不伪造无法从 DOCX 布局可靠取得的物理页码。法律条文外的非空文本不再静默丢弃，而标记为 `legal_unclassified` 供预览复核；这可能增加少量需要人工检查的块，但优先保证内容完整性。
