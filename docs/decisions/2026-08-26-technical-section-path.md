# 技术书切分章节路径修复决策记录

## Problem

VL Markdown 中的技术书章节标题已经被识别，但部分带有中文“第…章/节”或数字层级的标题未稳定建立章节路径，导致正文及续块缺少检索上下文；同时，VL 会把正文式导语（如“## MetaGPT：SOP …。”）误标成二级 Markdown 标题，原规则据此重置了章节根路径。

## Decision

在 `chunk_technical_book` 中使用 `_heading_depth` 只识别带结构化编号（第X章/1.2.3）的标题来更新章节路径，按编号层数而非 Markdown `#` 数量定位层级；不编号的正文式标题一律作为 subheading，不重置路径。正文、代码、表格内容及长度续块继续复制当前路径。目录过滤和无章节的封面信息保持现状。

## Alternatives

- 为每个输出文件手工补写 `section_path`：只能修复单个结果，无法覆盖后续文档。
- 改用模型重新推断章节：增加不确定性，且标题层级是可由规则确定的结构信息。

## Consequences

技术书 chunk 能携带稳定的章节上下文，便于检索和审计；新增回归测试覆盖一级/二级/三级标题、正文、代码、表格内容和续块路径继承。目录页和无章节封面块仍可能保持空路径，这是有意保留的行为。
